# Implementation and runtime report

## QP-feasibility review revision

Code inspection confirms that `solve_cbvf_projection_exact` implements the intended minimum-distance projection whenever the affine constraint is feasible. When the requested constraint is infeasible and `a_u` is nonzero, its documented least-violation action maximizes the affine left-hand side and is therefore an actuator rail. When `a_u` is effectively zero, it keeps the nominal action because control cannot improve the constraint.

The previous training integration exposed only `infeasible=true` and continued executing that fallback, so a run with almost one fallback per intervention could still finish and be misread as calibrated-QP validation. This revision changes that behavior:

- strict/full runs abort before executing the first infeasible CP action;
- before RL begins, every stored certified CBVF grid node in the CP activation/hysteresis band is audited; strict training requires zero negative feasibility margins on that discrete set;
- `--allow-infeasible-cp-diagnostic-run` is an explicit short-run-only override;
- every selected active evaluation step prints and saves `xi_hat_app`, `epsilon_inter`, requested RHS, `max_u_psi`, feasibility margin, achieved margin, affine terms, actions, and fallback type/bound;
- feasible outputs are independently compared with the analytic one-dimensional closest projection;
- a diagnostic run containing any fallback is labeled invalid for a calibrated-QP/Assumption-5 claim;
- the no-filter curve is labeled as a counterfactual unshielded diagnostic of the shield-trained actor, not a separately trained nominal baseline.

The later feasibility audit found and removed a hard-coded `0.10` conformal
quantile ceiling; retaining it would invalidate coverage. A stationary-table
time-axis compatibility correction was also added. No QP-RHS clipping,
alternate fallback, ACI, partition change, or alternate conformal method was
introduced. See `results/FEASIBILITY_BLOCKER.md` for the subsequent exhaustive
aligned-model diagnosis.

## Implemented workflow

- The RL agent is initialized from scratch; the training entry point has no checkpoint-restore path.
- The finite-horizon CBVF is requested with `recompute=True`, and training aborts unless the table reports that it was freshly built.
- The frozen initial actor collects all calibration rollouts before the first RL reset or optimizer update.
- Calibration calls the finalized `calibrate_mondrian` implementation. That implementation uses the baseline CBVF-QP with `method="cbvf"` and `xi=0.0`.
- Training always calls the conformal shield with `method="cp"` before `env.step`.
- The regional buffer is selected with `MondrianCalibration.applied_buffer`, including every effective region intersected by the one-step speed-envelope tube.
- Replay stores the filtered action and the reward, cost, and next observation generated by that action.
- Every transition logs nominal, filtered, and environment-applied actions in `training_actions.jsonl`.
- `conformal_shield.py` contains only the two audit corrections described above.
- Replay uses `mask = float(not terminated)`: truncations bootstrap, true terminals do not, including a simultaneous terminal/truncation event.
- The registration-time 400-step constant was removed. Train and evaluation environments are created with `max_episode_steps=args.horizon`; startup assertions bind the Gym TimeLimit and internal environment horizon to the CBVF horizon.
- Calibration uses the environment's exact initial-state sampler. Calibration, training, and evaluation reject any realized start with `B(x0,t0) < 0`, so the two distributions are never silently conditioned differently.
- Nominal, baseline-CBVF, and conformal evaluation use identical per-episode seeds/start states.
- The manifest reports closest-region calibration count, the per-base-leaf minimum, effective groups, and candidate-region statistics. A full run aborts before RL training if `n_effective_regions <= 1`.

Paper-level caveat: the finite-sample Mondrian coverage statement applies to a new rollout from the same fixed reference policy used for calibration. The RL policy changes during optimization, so the pre-training buffers remain active deterministic margins during training, but the paper's exchangeability-based coverage probability does not automatically transfer to every later policy iterate.

- `gymnasium`;
- `jax` and `jaxlib`;
- `flax`, `optax`, `distrax`, and `ml_collections`;
- `heterocl`;
- the `optimized_dp/odp` source tree;

The supplied archive did not contain the last two project-specific HJ dependencies. Because the environment cannot access the required Python package source and the HJ files were not attached, the RL smoke/full runs could not proceed.
